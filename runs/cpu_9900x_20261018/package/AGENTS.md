# AGENTS

本文件只约束编码代理的通用工作方式。项目的系统模型、算法定义、实验参数和阶段状态应
分别写在相应文档、配置与结果中，不在这里重复。

## 工作原则

1. **独立思考，不迎合。** 根据公式、代码、实验和可靠文献形成判断。发现用户的设想、
   既有实现或参考论文可能有问题时，应直接说明证据、影响和可行替代方案。

2. **不要过度防御。** 对不影响研究结论的细节作合理假设并继续推进，不把一般的不确定性
   都升级成阻塞或“硬停止”。只有在问题会实质改变模型、结论或实验有效性时才暂停确认。

3. **以学术研究为中心。** 优先保证理论无误、论证有来源、实验可复现、代码能运行且性能
   有竞争力。避免为尚未需要的生产部署、接口兼容、抽象层次或极端边界进行过度工程化。

4. **合理看待误差。** 数学恒等式和确定性基准应达到与数值精度相称的误差；学习算法、
   Monte Carlo 估计和迭代推断应使用有统计或数值意义的指标与容差，不要求不现实的零误差。
   不得为了宣称成功而删除不利样本、隐瞒失败或随意放宽标准。

5. **证据透明。** 明确区分已验证事实、合理推断和待验证建议；不得编造引用、结果或已完成
   的实验。使用真值、oracle、proxy 或模拟数据时应清楚标记。

6. **保持简单和聚焦。** 在满足研究目标的前提下选择最小充分实现。保留用户已有改动，
   不扩张到无关任务；修改后执行与风险相称的测试，并清楚报告结果和局限。

7. **术语必须有论文出处。** 公式推导、算法说明和论文稿中的专业术语、方法名称及技术
   表述须采用已有论文的原词或忠实中文译名，核对原文含义并记录章节、公式或页码；不得
   自造术语、缩写或把自拟组合包装成既有名称。无对应名称时，使用已有术语和公式直接
   描述操作。术语依据统一记录于 `docs/TERMINOLOGY.md`。

8. **不自动启用 Git。** 用户已要求停用本项目的 Git 自动快照。不要自行运行
   `git init` 或恢复 `.git`；仅在用户明确要求重新启用 Git 时恢复。历史保留位置与
   恢复记录见 `results/snapshot_disable_20261014/SUMMARY.json`。

9. **保留已冻结的研究主线。** 以 `MAINLINE.json` 及其链接的主线说明为准。候选修改
   使用独立的实现、配置、权重与结果路径，不覆盖冻结副本；切换主线前保留旧版本和
   配对验证记录。常规文件清理默认排除已冻结的主线资产。
