# C-STMP 估计相位接入与小样本配对验证

## 范围

用户授权只接入相位估计、用少量 SNR 场景检查相对已知相位的性能变化；不启动全量实验、不影响正在运行的用户数批次。
候选实现位于 `src/algorithm/C_STMP_phase_frontend_20261027/`，独立绑定为
`src/configs/candidates/C_STMP_phase_frontend_20261027.json`。全局算法目录、FINAL、现行 C-STMP、STMP 及用户数批次的配置均保持原文。

本轮先复用 `system.receiver.phase_estimation` 的已有前端，由公开观测和原始导频估计各候选用户的跨帧相位，再固定该相位运行当前 C-STMP。
这是“先估计相位，再运行条件接收机”的实现，不是 STMP 内部联合相位更新。每用户一条主导路径的近似只用于相位拟合，不改变 C-STMP 最终的完整信道表示。
噪声方差在前端和条件接收机中均由同一观测估计。未知相位入口忽略输入噪声占位值；不读取真实相位、活动数或信道。
已有 `ReceiverInput` 只用于明确标注的已知相位控制路径，不能作为未知相位的输入。

## 配对与资源

- 在看到候选输出前固定场景 0、1、2，各取 −4、0、6 dB，共 9 组。
- 所有观测、原始导频、活动先验、真值及已知相位参考直接复用已完成的 1000 场景 SNR 批次；输入哈希、参考预测哈希和参考重评分在准备时核验。
- 一阶权重、分类器、查询方差处理、阻尼 0.4、0.5 判决门限、60–600 轮及停止容差保持不变。
- 首先重放 scene0/−4 dB 的已知相位控制，核对 CPU 与已保存 GPU 结果。冻结容差：NMSE 绝对差 ≤0.001 dB、概率最大绝对差 ≤0.0001、信道相对误差 ≤0.0001，活动判决、停止原因和轮数完全相同。未通过则停止本诊断，不放宽标准。
- 新增推断最多为 1 次已知相位控制和 9 次估计相位结果；没有训练或全量扫描入口。
- CPU 单进程，Torch/BLAS 各 1 计算线程，Windows 空闲优先级，CUDA 对本进程不可见。进程常驻内存上限 2.5 GiB，系统可用内存低于 0.85 GiB 时只停止本诊断。用户数进程和调度文件不写入、不暂停、不重启。

## 评分与解释

NMSE 沿用汇总误差能量与信道能量之比；AER 沿用漏检加虚警占全部用户判决的比例。
报告每档及逐场景的估计相位减已知相位 NMSE 差（正值为退化）、AER 绝对增量、漏检/虚警数、停止轮数与停止标签。
相位诊断只在推断结束后，针对真实活动用户及 q>0 帧计算单位复相位的均方差；其真值只用于评分。
所有有限非收敛输出均保留，不按结果选择场景，不把小样本零 AER 当作总体零错误率。
3 个物理场景重复用于三档 SNR，不能视为 9 个独立场景；这也是此前查看过的开发数据，不作独立确认或显著性主张。
CPU/GPU 控制重放只检查一个输入，不能保证所有输入逐元素完全相同；变化小于数值差异量级时不作解释。
并发环境中的耗时只用于运行追溯，不作算法时延比较。

相位拟合的原词、含义及原文定位沿用本稿 `TERMINOLOGY.md` 的 2026-10-15 未知跨帧相位条目：

## 完成结果

9组全部收敛。−4、0、6 dB的合并NMSE损失依次为0.701952、0.811986、0.808763 dB；逐场景损失范围0.261959–1.456758 dB。
所有活动判决逐用户相同，−4 dB均为1次漏检、0次虚警，另两档无错误。
CPU/GPU控制重放的NMSE绝对差为0.000003567 dB，判决、停止轮数和原因一致；181份绑定资产哈希均未变化。
用户数主进程及6个工作进程身份相同，诊断运行期间结果数由1462增至1577，无新增运行失败；诊断不使用GPU，常驻内存峰值约1.065 GiB。
这只支持本次3个固定物理场景中存在有限但可测的信道估计损失，未观察到检测退化；不能解释为一般条件下相位误差可忽略。
本轮完成后已退出，没有启动全量相位实验或训练，也没有改写论文正文及正式图。
