## 推断与待验证方案

候选替换频繁触发状态和停止窗口重置，是值得优先检查的机制；现有数据是关联证据，
尚未证明某项调度修改能改善收敛、误差或运行时间。

建议先保持物理前端、网络、阻尼、门限及最大迭代预算不变，优先独立验证：
1. 候选替换后先完成普通相位细化和信道重估，再允许下一次候选检查，
   避免候选检查持续抢在普通细化之前；保留全部用户检查，不能按当前硬活动判决排除漏检用户。
2. 将廉价相位细化和昂贵的全部用户候选检查分开调度；候选检查在停滞或拟停止时执行。
3. 将停止判断与固定20轮相位检查边界解耦，仍保留最终相位/信道一致性和活动稳定性检查。
4. 若上述验证显示值得继续，再单独比较更早的小步相位更新以及更便宜的初始化，
   避免同时改动所有部件后无法判断收益来源。

不直接删除检测候选，不随意放宽收敛标准，也不把固定高斯消息下降推广为整体神经接收机保证。
后续验证应在独立候选路径保留旧结果，包含普通、低SNR未收敛、反复替换及大损失案例，
并用未参与调度选择的场景核查；未经用户后续指示，本次不修改或运行这些候选。
