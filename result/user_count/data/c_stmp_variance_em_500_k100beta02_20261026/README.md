# 用户数500场景：仅100用户采用β=0.2

用户于2026-10-26授权：“100用户的时候，阻尼改成0.2，其他的不变继续跑”。

本批次固定场景0–499及20/40/60/80/100用户五档。只有100用户档的`ep.damping`从0.4改为0.2；其他档仍为0.4。600轮上限、至少60轮、全部收敛条件、权重、分类门限、探针、估计噪声和输入均不变。全局默认配置、既有SNR/导频和原冻结批次不改。

原`c_stmp_variance_em_500_resumed_20261026`通过`parallel7/STOP.json`保存全部在途结果后退出。新批次先核对原主进程及工作进程退出，再逐份验证和重评分复用20/40/60/80用户的所有已完成结果。原100用户β=0.4结果保留为对照，不混入新图，也不按是否收敛挑选复用。

独立GPU诊断`c_stmp_100user_beta02_gpu_20261026`的15例保持运行；这15例已采用完全相同的β=0.2配置，全部预留并核验复用。其余485个100用户输入统一重新/首次使用β=0.2。诊断未完成或未通过验证时不能自行重试或用旧结果补位。

接续保持7个GPU工作进程、每进程2线程。每个进程只加载一套相同网络，按公开用户数选择完整配置和`SpatialConfig`；接收机每次推断重置模型状态，网络与算法源码不变。正式首批保存输出用于检查，不额外推断预检。失败不自动重试；`STOP.json`停止派发并保存在途结果；七天上限。

最终固定2500份C-STMP结果与10000份历史baseline配对重评分。NMSE为总误差能量/总信号能量，AER含漏检与虚警；保留有限未收敛结果。图沿用前一批冻结的样式和baseline门限，AER概率对数轴，零值单列。用户数每档500场景完成、核验并展示图片后暂停，不运行下一实验。

本次阻尼调整发生在查看前100场景及部分诊断结果之后，属于回顾性参数开发；baseline门限开发也与评估场景有重叠。完整面板可以评价调整后的表现，但不能称为独立测试。共享GPU运行时间不用于证明算法时延优势。

实际状态见`STATUS.json`，进程身份见`START.json`；`HANDOFF.json`记录保留的原指针、原100用户对照、复用数量及新推断数量。最终图位于`result/user_count/figures/c_stmp_variance_em_500_k100beta02_20261026/comparison.png`。
