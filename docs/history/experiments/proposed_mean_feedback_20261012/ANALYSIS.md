## 结论及其边界

已有消融证明：在选出的三个失败条件中，即使不直接修正漏检用户的一阶输出、活动标签或分类器参数，改善其他真实活跃用户的条件均值也足以使整个迭代恢复检测。保存末态消息的进一步分解显示，其他已检出活跃用户的反馈误差确实向弱用户查询引入了较大的负向信号分量。这支持优先改善多用户均值估计及其反馈。

它没有证明某一个网络是唯一故障源，没有证明二阶信息或实际查询失配无关，也没有证明改进后的非oracle算法能够达到同样结果。共同标量方差是已发现的明确近似环节，但它是否导致主要均值误差仍待验证。

## 1. 原消融究竟改了什么

依据[冻结源码](../../results/proposed_ablation_20261012/mean_partition/source/closed_loop.py)中的 `IntervenedMoments` 和 `IntervenedEvidence`：

1. 用真实活动标签和原算法**最终**判决，固定分成原已检出活跃用户、原漏检活跃用户。不是每一轮依据当前概率选人。
2. 从第一轮起，每轮将第一组用户的条件均值替换为真实信道；第二组及非活跃用户的条件均值保持该次查询的原网络输出。
3. 二阶网络仍输出该次查询的原读数；活动分类器仍读取该次查询下原一阶网络的均值特征。没有把真值均值作为分类器输入，也没有直接指定活动概率。
4. 替换后的均值进入联合均值、Gaussian消息以及活动混合中的二阶项，因此会改变后续查询、概率、共同方差和迭代路径。不能称为“整个过程中只改了反馈均值而方差始终固定”。

| 条件 | 原算法漏检/虚警 | 只替换其他已检出活跃用户均值 | 只替换原漏检用户均值 |
|---|---:|---:|---:|
| 0 dB，场景49 | 2 / 0 | 0 / 0 | 0 / 0 |
| 0 dB，场景51 | 2 / 0 | 0 / 0 | 0 / 0 |
| 4 dB，场景95 | 1 / 0 | 0 / 0 | 0 / 0 |

两种均值干预都有效，说明至少存在两条可以打断失败状态的路径。表中的0错误只适用于三个已经挑选和查看的开发条件。该干预是从初始迭代开始，尚无“仅在原收敛末态修正其他用户均值”的对应闭环证据。

本次还逐项核实：场景49、95的首轮原运行与该oracle运行，分类logit、活动概率、二阶原读数、输入方差、联合方差完全相同。首轮所有概率都为1，活动混合的均值二阶项在这一轮恰好为0。后续结果分离由均值干预启动，但后续方差轨迹确实不同。

## 2. 其他用户的误差怎样进入弱用户查询

按[THEORY T3–T5](../../docs/THEORY.md)的完整向量记号，令 \(x_p\) 为反馈给线性模块的Gaussian输入均值、\(\gamma\) 为共同方差。定义

\[
G=\gamma A^H(\sigma^2I+\gamma AA^H)^{-1},\qquad
\kappa=\operatorname{tr}(GA)/(KD),\qquad L=G/\kappa.
\]

未阻尼查询的精确代数式为

\[
r^{\rm raw}=x_p+L(y-Ax_p),\qquad
r^{\rm raw}-x=(LA-I)(x-x_p)+Ln.
\tag{1}
\]

其中其他用户 \(j\ne k\) 对用户 \(k\) 的项是

\[
L_kA_j(x_j-x_{p,j})=-L_kA_j(x_{p,j}-x_j).
\tag{2}
\]

如果其他用户估计中的错误分量，经 \(L_kA_j\) 映射后与 \(x_k\) 同向，式(2)会削弱弱用户查询中的真实信号分量。这是带方向的误差传播；其作用不能只用总误差功率或一个噪声方差概括。这里的 \(x_p\) 是外信息反馈均值，不是直接把 \(pF\) 代入；本次分解读取的是实际保存的 \(x_p\)。

对保存的原末态，计算

\[
g_k=\frac{\operatorname{Re}\langle H_k,R_k\rangle}{\|H_k\|_F^2}.
\tag{3}
\]

理想无误差查询的该系数为1。该量需要真值，属于离线诊断，不是在线更新规则。场景49和95保存了完整原末态消息；以下未对场景51缺少的同类原消息作推测重建。

| 条件、用户编号（代码从0计数） | 原查询系数 \(g_k\) | 其他已检出活跃用户误差的贡献 | 热噪声贡献 | 均值oracle最终查询系数 |
|---|---:|---:|---:|---:|
| 0 dB，49，用户26 | 0.75148 | −0.33997 | −0.04670 | 1.01081 |
| 0 dB，49，用户27 | 0.61095 | −0.30824 | −0.08518 | 0.90114 |
| 4 dB，95，用户4 | 0.65007 | −0.40865 | −0.00055 | 1.02033 |

表中还有自身块、其他漏检用户、非活跃用户及查询阻尼历史的贡献，全部保存于JSON；它们与上表贡献相加后再加1，精确重建原 \(g_k\)。完整向量恒等式最大相对误差为 \(1.48\times10^{-15}\)。各项是沿真实信号的有符号分量，不是互相独立或可直接相加的误差能量。最后一列属于另一条完整oracle轨迹，不能解释成只删去第三列的一次更新。

因此，对这些末态，“其他已检出用户的误差削弱弱用户查询”已经有直接数值证据。它比仅观察到oracle更好更具体，但仍不是所有场景的总体归因比例。

## 3. 原算法中形成了什么问题

### 已检出不等于信道估计准确

场景49、95已检出活跃用户的条件均值NMSE（线性值）分别为0.10636和0.04160。即使活动概率达到1，这些矩阵误差依然存在。活动概率是活动事件的概率；它不表示信道均值可信度为100%，代码也仍保留 \(p\tau\) 这一方差项。

### 弱用户在条件均值和活动混合两处进一步衰减

原末态的三个漏检用户，\(R\) 沿真信道的系数为0.751、0.611、0.650；原一阶网络输出 \(F\) 的相应系数仅为0.0751、0.0680、0.0675。前两人的活动概率为0.01070、0.01249，第三人为约0.00021。联合均值 \(pF\) 因而接近0。

所以不能把问题简化成最后0.5门限偏高：输入和条件信道估计已经退化。原迭代可以按停止规则收敛，同时保持漏检。改善其他用户后，同一分类器能够恢复检测，说明分类器在更合适的查询上仍有能力；不等于它在所有实际查询上已经校准。

### 共同标量投影丢掉了用户间的不确定性区别

当前实现先在 `denoiser.py` 中将各用户二阶读数平均成共同 \(\tau\)，随后在 `iterations.py` 中将各用户联合协方差再次平均并投影成共同标量。局部联合矩本来包含

\[
\mu_k=p_kF_k,\qquad
t_k=p_k\tau_k+p_k(1-p_k)\|F_k\|_F^2/D.
\tag{4}
\]

场景49原末态，已检出活跃用户 \(p_k=1\) 时自己的联合平均迹为0.09955，最后给所有用户的共同值却是0.01773；场景95为0.03882对0.006797。差约5.6、5.7倍。活跃用户与多数非活跃用户被赋予相同的线性输入不确定性，这可能妨碍活跃用户继续修正完整信道矩阵。

这里指出的是共同投影的限制，**不是**证明该平均操作存在代数bug，也不是把网络报告的方差认作真实MSE。已有的“用真实联合MSE替换共同方差”控制仍只给所有用户一个数，不能检验保留各用户方差是否有帮助。

### 末态不是由外信息分母接近0造成的数值放大

原末态反馈 \(b=\bar t/v\) 分别为0.001687、0.001780，均值中的 \(1/(1-b)\) 只有1.00169、1.00178。查询阻尼历史对上述三个信号方向系数的贡献绝对值均小于0.001。因此当前末态损失主要不能用分母近零或“再加大阻尼”解释。此前取消查询阻尼导致失败的记录仍然成立；阻尼对迭代稳定有作用，但不是本次均值偏差的充分修复。

## 4. 为什么不优先做简单放大、无约束拟合或只改门限

- **整体复增益修正能力有限。** 本次用真值为每个已检出活跃用户单独求最优复标量 \(c_k\)，最小化 \(\|c_kF_k-H_k\|^2\)。即使给出这个oracle标量，两个场景该组总均值误差也最多分别下降7.62%、2.87%。这只是保存矩阵的最佳拟合误差，不是新增接收机评价。均值误差主要涉及矩阵形状；它不能证明任何小幅修正都不会改变检测，但不支持把全体放大作为主要方案。
- **仅降低观测残差不足。** 原线性模块已经使用 \(Y-AX_p\)。对已检出用户再做一次同样的无约束LMMSE并不构成新的依据；仅拟合这些用户还可能把遗漏用户吸收到它们的估计中。单个测量列中 \(Q=16\)，7个已检出用户就有 \(7P=112\) 个自由系数，必须保留信道先验或结构。
- **硬判活跃、冻结或调低门限不能替代估计。** 只提高 \(p\) 不恢复已经失准的 \(F\)；冻结已检出均值又会固定目前观察到的干扰误差。oracle最终0漏检也不意味着弱用户信道估计无误，例如49的用户26条件NMSE仍约0.634（线性值）。

## 5. 推荐先设计的修改：每个用户保留一个标量方差

目的不是增加网络输出维度，而是改变现有输出进入下一轮查询的方式，让原一阶网络有机会重新估计更准确的完整信道。三个权重、AWGN训练方式、\(pF\)联合均值和同查询分类器关系均保留。

这可采用已有文献的 **block uniform diagonalization**（分块均匀对角化）：每个用户作为一个块，块内仍采用标量乘单位阵。[Fletcher等，arXiv:1602.07795v2，§II-A式(8)–(9)、§II-B Algorithm 1，PDF pp.2–3](https://arxiv.org/pdf/1602.07795v2)。下面是本项目复数MMV模型的Gaussian代数推导；文献没有验证本项目有限网络的性能或收敛。

### 非线性输出及反馈

在每用户查询 \((R_k,v_k)\) 上，仍调用原一阶、二阶和活动网络得到 \(F_k,\tau_k,p_k\)，保留式(4)的 \(t_k\)。在 \(0<t_k<v_k\) 时，逐用户Gaussian相除为

\[
b_k=t_k/v_k,\qquad
Z_k=\frac{p_kF_k-b_kR_k}{1-b_k},\qquad
\gamma_k=\frac{b_kv_k}{1-b_k}.
\tag{5}
\]

实现时正方差、网络支持范围、Gaussian site拒绝及现有比值截断必须按用户处理并记录。发生截断时用截断后的 \(b_k\)，不能继续声称它等于原始 \(t_k/v_k\)。两向阻尼初始沿用当前0.1，活动仍软更新，不按0.5裁剪参与查询的用户。

### 线性模块构造不同的用户查询

采用实现的打包形式：\(Y\in\mathbb C^{Q\times MN}\)，\(Z_k\in\mathbb C^{P\times MN}\)，\(A_{0k}\in\mathbb C^{Q\times P}\)。以阻尼后的 \(Z_k,\gamma_k\) 为输入，构造

\[
C_y=\sigma^2 I_Q+\sum_j\gamma_j A_{0j}A_{0j}^H,\qquad
E=Y-\sum_jA_{0j}Z_j,
\]
\[
d_k=\frac1P\operatorname{tr}(A_{0k}^HC_y^{-1}A_{0k}).
\tag{6}
\]

该Gaussian线性后验块的平均迹为
\(t_{L,k}=\gamma_k-\gamma_k^2d_k\)。投影并除去该用户输入消息，得到

\[
R_k^{\rm raw}=Z_k+\frac{A_{0k}^HC_y^{-1}E}{d_k},\qquad
v_k^{\rm raw}=d_k^{-1}-\gamma_k.
\tag{7}
\]

随后做查询阻尼，回到原三个网络。式(7)避免先形成两个大精度再相减，且当 \(\gamma_k\to0\) 时，查询方差并不因此被强行置零。只要保留所有用户的查询与原软活动更新，低概率用户仍有再次获得证据的机会。

所需线性求解矩阵为 \(Q\times Q=16\times16\)；网络仍只接收标量 \(v_k\)。`FullChannelMoments.infer` 和活动网络的底层接口已经接受每样本不同的方差；需要修改的是外层Denoiser的共同方差检查、逐用户site及线性/反馈投影，不能只改一个平均语句。

这是一个具体、可实现的候选，但未验证优于原算法。即使所有 \(\gamma_k\) 相等，逐块迹一般也不全相同，故式(7)不必逐点退化为原全局迹查询；原模式应独立保留作对照。有限网络二阶读数仍是冻结均值的条件MSE近似，不满足精确GEC所需矩或Jacobian的保证；原有早期查询失配也可能继续存在。

### 为什么先改查询，而非随意后处理均值

直接将原 \(F\) 替换为任意精修 \(F'\)，再原样使用冻结二阶和分类器，会改变训练时的统计关系。令 \(\Delta=F'-F\)，\(\mathcal I\) 包含计算两种均值所用的信息，使两者在给定 \(\mathcal I\) 后确定，则

\[
E[\|F'-H\|^2\mid\mathcal I]
=E[\|F-H\|^2\mid\mathcal I]+\|\Delta\|^2
+2\operatorname{Re}\langle\Delta,E[F-H\mid\mathcal I]\rangle,
\tag{8}
\]

若 \(\Delta\) 还依赖其他观测，则须相应扩大条件信息，原二阶网络甚至未必针对此扩大信息下的原均值误差训练。现有二阶标量没有给出交叉项。只有额外成立 \(F=E[H\mid\mathcal I]\) 等条件时才能删去该项，实际失配查询上不能预设成立。

采用式(5)–(7)后，\(F_k\) 仍由原网络在同一个 \((R_k,v_k)\) 上生成，避免人为打断这三个模块的既有配合。但这种接口一致性本身不保证新的实际查询服从AWGN。

## 6. 验证顺序与停止边界

当前没有启动以下验证，也不安排自动运行。后续若恢复实验，先冻结候选与开发/确认样本，再依次回答：

1. 线性Gaussian后验及逐块外信息的代数是否正确；原算法模式能否原样复现。先做确定性小规模恒等式检查。
2. 先保留逐用户二阶读数但仍共同反馈，再比较完整逐用户标量反馈，区分两次平均的影响。已有三个均值oracle条件仅作开发；同时包括原来成功的场景。
3. 已检出用户的均值误差、它们在弱用户信号方向造成的误差、弱用户 \(R,F,p\) 是否一起改善。真值只评分，不进入候选输入、用户选择或超参数。仅残差下降不能算修复。
4. 报告全部MD/FA、NMSE、未收敛、site拒绝/截断和计算代价，并在未用于选择方案的物理seed上确认。不能用三个旧失败条件的0错误宣称总体优势。

如果逐用户标量反馈没有改善已检出用户的矩阵形状误差，就说明该近似不是充分修复。届时再研究有明确约束的联合均值精修，或保持架构的实际查询训练，并同步处理二阶目标和分类器特征；不把本次oracle成功直接当作这些方案已有效的证据。
