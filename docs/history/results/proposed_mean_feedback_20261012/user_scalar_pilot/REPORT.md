## 本轮判断

**较小的改动在一个困难条件减少了1个漏检；完整逐用户反馈没有减少漏检。** 不能据此采用完整候选，也不能把四个物理场景的开发结果推广为总体改善。

三个版本使用相同的原一阶、二阶和活动网络。原算法先平均二阶输出，再形成联合矩与共同反馈；“逐用户二阶读数”先为每位用户保留其二阶标量，形成联合矩后仍采用原共同反馈及线性更新；“完整逐用户反馈”进一步将反馈与线性查询都改成逐用户标量。推断均不使用真实活动标签或信道。

0 dB场景49、51的四个漏检没有消除。较小改动恢复了4 dB场景95的用户4，三个正常条件均保持0漏检、0虚警。完整候选的总漏检与原算法相同，聚合NMSE也没有改善。八项确定性测试与六条件的原算法复现均通过，这支持当前实现可用于这次比较；代数检查不能替代性能验证。

## 为什么较小的改动与完整改动结果不同

在同一查询上且Gaussian site接受、条件方差未触底时，两个版本的一阶均值F_k和分类器概率p_k相同。本批次三个困难条件的所有查询均满足上述条件。较小改动首先改变的是联合矩中二阶输出的加权顺序。令D=MNP，原共同后验标量为

\[
\bar t_{\rm original}=\bar p\,\bar\tau+
\frac1K\sum_k p_k(1-p_k)\frac{\|F_k\|^2}{D},
\qquad
\bar t_{\rm conditional}=\frac1K\sum_k p_k\tau_k+
\frac1K\sum_k p_k(1-p_k)\frac{\|F_k\|^2}{D}.
\]

两者差为平均(p_kτ_k)−平均(p_k)平均(τ_k)。它通过原Gaussian外信息和后续查询改变迭代，而不直接修正同一次查询的一阶均值。该式由现有联合矩及各向同性投影直接得到，见项目THEORY的T16–T17；不把二阶网络的条件MSE读数当作已经认证的精确后验协方差。

在4 dB场景95，较小改动的用户4从第122轮起一直保持p≥0.5，直到第189轮满足原停止条件；原算法在第250轮停止时仍漏检。其保存末态如下：

| 量 | 原算法 | 逐用户二阶读数 | 完整逐用户反馈 |
|---|---:|---:|---:|
| 用户4查询方向系数 | 0.6501 | 0.7749 | 0.6521 |
| 用户4条件均值方向系数 | 0.0675 | 0.4654 | 0.0687 |
| 用户4条件均值NMSE（线性比值） | 0.9645 | 0.5219 | 0.9633 |
| 用户4活动概率 | 0.000209 | 1.000000 | 0.000229 |
| 其他原已检出活跃用户反馈误差的查询贡献 | −0.4087 | −0.2610 | −0.3678 |
| 其他原已检出活跃用户条件均值NMSE（线性比值） | 0.04160 | 0.03953 | 0.04168 |

![场景95用户4的活动概率与查询轨迹](scene95_trajectory.png)

图中每条线止于各自原规则判定的收敛轮数；没有补齐或外推。此条件用于展示本面板唯一恢复检测的案例，完整面板已在上表展示。均值估计改善、活动恢复和反馈改变发生在同一闭环中；不能仅根据末态认定是其他用户均值先改善导致恢复。

完整改动虽降低了上述负贡献的幅度，但同时改变了其他贡献；例如该用户的非活跃用户误差贡献由+0.03738变为+0.000013。最终查询系数仍接近原值。0 dB场景49中，完整候选的输入反馈方差已分布在0.0000311～0.1216，查询方差却仅分布在10.5007～10.5643，两个漏检用户的查询几乎未变。

从线性公式看，用户自己的输入方差γ_k在Gaussian相除后的查询R_k=Z_k+A_kᴴC_y⁻¹(Y−AZ)/d_k中不再作为直接乘数，只通过C_y和d_k影响查询。因此“γ_k差异很大”不保证“弱用户查询明显改善”。场景49的完整候选末态，算法建模的A diag(γ) Aᴴ相对于σ²I的特征值为0.0325～0.1219，与查询变化有限相容；这是建模不确定性，不能解释为真实残余干扰功率很小。

此前oracle结果依然说明改善其他用户均值及其反馈可以解除所选漏检，但**本轮没有证明逐用户方差本身就是充分修复**。当前保留原算法为默认实现；较小改动作为开发候选保存，后续若继续，应先在新物理场景确认其检测收益，同时继续研究直接改善均值的办法。本轮没有启动后续实验或训练。

## 可复核性与范围

- 三个权重和原20项源码/配置身份保持不变；输入及输出文件身份核对通过。六个原算法复现的估计与概率差均为0；全部末态误差传播恒等式的相对误差不超过1.51e−15。具体差值在VALIDATION.json。
- 八项确定性测试通过，并进行了单用户完整循环的新旧代数核对；预检时发现并修复一个失败阶段记录位置问题，未改变候选数值更新，历史保存在PREFLIGHT。
- `RESULTS.json`保留各条件收敛、支持范围、site拒绝、截断、网络调用、耗时和异常。真值观察器的耗时包含在本批次墙钟时间内，不把此计时直接作正式算法速度比较。
- 本批18次均有有限输出、满足原停止规则，无site拒绝或超出网络支持范围。正常场景0在0 dB、4 dB下的每个版本均有一轮触发条件方差下限；三个困难条件未触发该下限。完整逐用户反馈另在场景95、0 dB场景0、4 dB场景0分别有188、83、115轮触发沿用的方差比例截断；这属于实际候选更新，未在结果中剔除。其中场景95的方差比例均为下限截断，未触发上限。本批没有单独隔离截断的效果。
- 原算法及逐用户二阶读数各六次运行均记录了matmul的divide-by-zero、invalid及overflow警告；完整候选未记录该警告。所有末态有限、原算法复现完全一致，警告原文仍保存在各RESULT中，不将“无数值失败”写成“无运行警告”。本轮没有为消除警告改写原算法。
- 本轮不训练、不调门限或阻尼、不改变默认算法；若开发候选有效，仍需另行冻结并在新物理seed上确认。
